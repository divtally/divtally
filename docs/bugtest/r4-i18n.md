## 1. Non-ASCII end-to-end (Part A) — all PASS

### 1.1 Both URL paste forms load the Cyrillic build (double-encode safe)
A real user pastes one of two forms; both were tested and both resolve to the same character:

| Form | Pasted `#url` | Result |
|---|---|---|
| **(a) percent-encoded** (what Chrome copies from the address bar) | `…/Poteitik-3151/%D0%9F%D0%9E%D0%A2%D0%95%D0%99%D0%A2%D0%98%D0%9A` | `phase=done`, 27 items, `meta.character="ПОТЕЙТИК"` |
| **(b) raw Cyrillic** | `…/Poteitik-3151/ПОТЕЙТИК` | `phase=done`, 27 items, `sameAsEncoded=true` |

Why both work (traced in source): the client sends exactly **one** `encodeURIComponent(input)`
(`core.js:351`); the server's `parse_qs` decodes the query **once** (`build.py:108`); then
`poeninja.py:86` `urllib.parse.unquote`s the path segment **once**. Net one decode lands on `П` in
**both** cases — form (a)'s `%25D0…` → `%D0…` → `П`, form (b)'s `%D0…` → `П`. No double-decode / no
under-decode. (This is the classic i18n break; it is absent here.)

### 1.2 Name renders with zero mojibake, everywhere
`#bName` = `"ПОТЕЙТИК"` (exact); `meta.character` = `"ПОТЕЙТИК"`; both `mojibake:false` against a
detector for UTF-8-as-latin1 (`Ð/Ñ/Ã…`), `U+FFFD`, and leaked `%`-literals. Rendered clean in the
banner, in **both** Recents rows, and in the two "Saved characters" portraits (see
`r4i18n_name_banner.png`, `r4i18n_phone_full.png`). Name still `"ПОТЕЙТИК"` **after** the scan
(`nameStillOK=true`) and at 1920 (`v2.nameOK=true`) — no corruption under state churn.
> The `source_url`/`bpc_recent_builds` "mojibake" flags my detector raised are **false positives**:
> they matched the `%D0` inside the *legitimately* percent-encoded URL string of the encoded-paste
> entry — a correctly-encoded URL, never a rendered display string. The stored `character` field is
> clean raw Cyrillic (`"character":"ПОТЕЙТИК"` in the raw localStorage dump).

### 1.3 Cache keys stable (hex, no mojibake) — including the write path
Per-item cache key = `"v1_" + SHA-256(leagueKeyspace + GS + itemIdentity)[:32]` (`core.js:314`).
The Cyrillic character name is **not** in the key material (identity is league + English item base +
mods), and the output is pure hex, so the key is **mojibake-immune by construction**. Live: **12/12**
item keys match `^v1_[0-9a-f]{32}$` (e.g. Cataclysm Hand → `v1_f21379a12807c09049cc243f6261a7cc`,
Maloney's Mechanism → `v1_9609789469556cfb90b1351d5f580d1f`), `deterministic=true` (recompute equal),
`anyMojibakeKey=false`, and the **first key is byte-identical before vs after the scan**
(`keyStableAcrossScan=true`). The scan's **5 cache POSTs** to the worker succeeded → the Cyrillic
build both **reads** and **writes** the community cache on stable keys. Because the char name is
absent from item keys, an English build's scan of the same item hits the **same** KV entry — cache
sharing is unaffected by locale.
> Server disk-cache key (`meta.cache_key`, used only for the client's per-build purchase-tracking
> localStorage key) is `poeninja:char:0920-20260728-43586:Poteitik-3151:ПОТЕЙТИК` — carries raw
> Cyrillic cleanly and deterministically; JS localStorage keys are unicode-native, so it round-trips.

## 2. Viewport (Part B)

### 2.1 R4I-1 (minor) — ~27 px horizontal body overflow at 375×812
`document.documentElement.scrollWidth = 402` vs `innerWidth = 375` (emulation confirmed at 375).
Box-model root cause (computed styles, phone viewport):

| element | width | right edge | notes |
|---|---|---|---|
| `.doll-wrap` / `.doll-wrap .frame` | **384** | **402** | border-box, no padding/border/margin/min-width — width imposed by the `.board` `1fr` grid track, which isn't shrinking below ~384 px |
| `.doll-wrap .inner` / `.panel-head` | 378 | 399 | `.panel-head` is `flex` **nowrap**; holds "Equipment · legend · weapon swap · toggle all" |
| `#doll` | 378 | 399 | 18 px side padding each side |
| `#doll .slot` / `.iname` | 307 / 303 | 381 / 379 | item rows fit individually |
| `.grp-toggle` ("toggle all") | 57 | **385** | farthest-right leaf, 10 px past the 375 viewport |

The `.board` collapses to one column at `≤720px` (verified) but the doll region retains an intrinsic
~384 px width and doesn't clamp to the narrower viewport, so the shared page container renders ~402 px
wide and the body scrolls ~27 px sideways. **Graceful:** the page is fully usable — vertical scroll
works, nothing is clipped away, every control is reachable, Cyrillic renders. **Fix:** add
`min-width:0` / `max-width:100%` to the `.board` grid children (`.doll-wrap`,`.stash-wrap`) and/or
trim the `#doll` 18 px side padding + slot sizing at the `≤720px` breakpoint so the doll shrinks to
the container. Cheap; cosmetic.

## 4. Method / reproduction

   `Poteitik-3151/ПОТЕЙТИК` (OK) + enumerate the ladder's non-ASCII names (8 Cyrillic fallbacks).
2. `chromium.launchPersistentContext(scratchpad\r4i18n, {headless:false, --load-extension=<ext>})`,
   `bpc_autoscan_auto='0'` to control the single scan.
3. **I1/I2** fill `#url` with the encoded then raw URL, click `#go`, read `meta`/`#bName`/mojibake.
4. **I3** `await bpc.cacheKey(league,item)` ×12 → assert `^v1_[0-9a-f]{32}$`, determinism, no moji.
5. **I4** read `bpc_recent_builds`, reload, assert ПОТЕЙТИК recent, click portrait, assert reopen.
6. **I5** click `#autoscanBtn`, drain to stable (`totalMs`, 0 stuck), recompute key (stable).
7. **V1** `setViewportSize(375,812)`: fullPage + region shots; measure `scrollWidth` vs `innerWidth`,
   per-control bounding boxes, legend/rares in-bounds; open picker (`#pickwrap.show`/`.pick`) and
   measure fit + internal scroll + button bounds. **V2** `setViewportSize(1920,1080)`: overflow + name.
- **Harness note:** the main driver first queried the picker as `.pickwrap.show` (class); the element
  is `id="pickwrap"` (no such class), so it reported a false `noModal`. Re-probed with the correct
  `#pickwrap.show` (`r4i18n_picker.mjs`, trade-free) → picker opens and fits (§2.2). Recorded so the
  false-negative isn't mistaken for a defect.

worker cache calls; **0 direct pathofexile.com calls from the page**, 0×429, 0 aborts, 0 pageerrors.
